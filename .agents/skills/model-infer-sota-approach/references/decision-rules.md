# 状态裁决与 round 推进规则

本文件供主 agent 使用：候选发现完成后初始化 Dashboard、每轮 implementer / reviewer 返回后裁决 Plan 状态，以及在两个 round 之间决定是否重采 profiling。领域 skill 的正确性要求优先于本文件。

## 初始化 Dashboard 的前提

Dashboard 在下列场景、基线和候选证据齐备后初始化：

- 推理场景以及精度 / 功能口径已经记录在案。
- 场景已经跑通；即便被阻塞，也已查清阻塞原因，且用户仍要求继续分析。
- baseline 的 profiling 采集方式已经建立，或者已有可直接复用的 profiling 数据。
- baseline profiling 已经分析完毕，产出了可回查的分析报告。
- 至少有一个 candidate subagent 返回了候选，或者本次所选来源均已确认无合适候选。

用户提供的优化列表作为初始候选，由 candidate subagent 或主 agent 规范化后纳入 Dashboard。

## 状态定义

全程只允许三种状态：

| 状态 | 含义 |
| --- | --- |
| `待实现` | 尚未实施，或证据不足但仍有继续实施、调测的价值 |
| `通过` | 有明确收益或必要价值，且功能、精度、回退路径和副作用都已检查通过 |
| `淘汰` | 不满足保留标准且已无继续调测价值，或被同一互斥组里更优的 Plan 替代 |

## 通过条件

下列条件全部满足才能标 `通过`：

- reviewer 独立验证通过；结论有争议时，主 agent 核查证据并安排复验后裁决。
- 该 Plan 的代码路径在第一步确认的推理场景中实际执行。
- 功能和精度满足第一步约定的口径。
- 达到该 Plan 已确认的保留标准；未设数值目标时，说明保留价值，例如为后续 Plan 释放资源或消除特定瓶颈。
- 启用方式与回退路径清楚可用。
- 与本轮继续保留的已通过 Plan 兼容。
- 若属于互斥组，组内当前没有比它更优的已通过 Plan；否则先处理替代关系再裁决。

## 淘汰条件

出现下列任一情况，优先标 `淘汰`：

- 诊断或复验表明方案不可行，或修复代价超出本次范围。
- 未达到已确认的保留标准（如收益不超过测量波动），且已无继续调测价值。
- 副作用超出已确认的可接受范围，如其他关键模块性能下降、内存占用显著增加、额外 shape / layout 转换、图模式退化等。
- 与已通过 Plan 冲突，而它本身收益更低或风险更高。
- 同一互斥组里已经有更优的 Plan。

标记为 `淘汰` 后记录淘汰证据、代码回退或 enable 关闭状态，以及是否派生新 Plan。

## 保持 `待实现` 或追加 round

下列情况可保持 `待实现`，或新增 round 继续验证与调整：

- 实施尚未完成，但阻塞问题可修复。
- reviewer 指出证据不足，需要补充验证。
- 方向成立，强度、参数、配置或局部实现仍需调整。
- 本轮暴露了新问题，但还不足以证明 Plan 本身无效。

## round 之间是否重采 profiling

每轮结束、选择下一 Plan 时，主 agent 判断现有 profiling 数据是否足以支撑后续验证，并确定是否重新采集。

**需要重采**——依次派发 profiling-instrumenter 与 profile-analyzer，采集本轮 profiling 数据并生成分析报告；分析配置按 perf-breakdown 的复用规则核对与更新：

- 待验证的改动改变了算子下发时序、计算图结构、dtype 或 layout。多流、融合算子、图模式、量化改造通常属于此类。
- reviewer 指出现有 profile 与当前代码不匹配，不足以判断收益。
- 转向新的优化方向，或深入分析此前未采集的热点模块。
- 当前收益或副作用的判断需要新的时间线、算子或资源证据。
- 进入最终验收前，对最终代码路径至少重采一次，用来与 baseline 做同口径对照。

**可以不重采、沿用现有数据**：

- 已有 profile 对应当前执行路径、配置与负载，且覆盖本轮所需分析。
- 本轮只需目标指标的对照测量，已有 profile 足以支撑瓶颈分析；注释等不影响执行的改动可直接复用。

性能收益按当前执行路径的目标指标实测判定，记录场景、配置、预热范围与波动；profiling 用于解释时间分布、瓶颈及副作用，理论对比启用时再参考实测 / 理论 gap。复用分析规则时，按 perf-breakdown 的小改 / 中改 / 大改判断更新 sample 和统计；已有测量仅在执行路径、配置、负载与测量方式仍一致时复用。

## 派生新 Plan

implementer、reviewer 和主 agent 均可建议派生，由主 agent 写入 Dashboard。保留旧 Plan 记录，新 Plan 使用独立编号。常见触发条件：

- 当前 Plan 的核心假设被推翻，但证据指向了另一条可行的实现路径。
- 同一优化点存在尚未验证的编排、算子、参数或图模式路径。
- implementer 发现原方案实施成本过高，但可先验证范围更小的方案。
- reviewer 确认当前实现有收益，但还有风险更低或收益更高的变体值得一试。
- 当前实现路径不适用，但优化方向仍有验证价值。
- 多个已通过 Plan 组合后出现退化，需要派生针对组合问题的 Plan。

派生记录包含：来源 Plan / round、提出角色（implementer / reviewer / 主 agent）、触发现象及新旧 Plan 差异；新 Plan 初始状态为 `待实现`。

## 互斥与叠加

- 同一互斥组最终只保留一个、或一组明确兼容的 `通过` Plan。
- 新 Plan 替代旧 Plan 时，把旧 Plan 改为 `淘汰`，原因写明"被 Plan-X 替代"。
- 可叠加 Plan 可以同时通过，最终验收须实测组合后的代码路径与指标。
- 两个单独通过的 Plan 组合后若退化，追加一个组合验证 round；必要时淘汰组合收益更差或风险更高的一方。

初始化 Dashboard 时，由主 agent 汇总各 candidate 的分析，识别跨方向冲突并标明互斥组与可叠加性，例如融合算子与多流对同一段 attention 的改动，以及图模式与多流的兼容关系。

## 最终验收

结束前逐项确认：

- 本次探索已结束，记录停止依据；未验证 Plan 保留 `待实现` 并注明后续建议。
- 所有 `通过` Plan 都在最终代码路径里真实生效。
- 未采纳的试验改动已回退或被开关关闭。
- 互斥组状态自洽，组内只剩最终采用的方案为 `通过`。
- 可叠加 Plan 的组合效果已经实测验证。
- 最终精度 / 功能仍满足第一步约定的场景口径。
- 最终性能按 baseline 同场景、同指标口径实测，并有最终 profile 支撑收益归因。
